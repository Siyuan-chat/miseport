# Cloudflare Pages Advanced Mode and optional Workers adapter

The current deployment uses **Cloudflare Pages Advanced Mode**, combining static files and a bundled `_worker.js`. On 2026-10-29, dashboard Direct Upload reached global deployment success at [miseport.pages.dev](https://miseport.pages.dev), with MCP at `https://miseport.pages.dev/mcp`. A real Python SDK HTTP client initialized, listed seven read-only tools and invoked every tool successfully. Public website/assets, guide, health, OpenAPI, REST and expected error responses also passed. Local evidence: `artifacts/public-demo-acceptance.json`, `artifacts/cloudflare-pages/manifest.json` and `artifacts/cloudflare-pages/deployed.png`. Reproduce the bounded read-only public check with `python scripts/probe_public_demo.py`. **Muse account connectivity is pending login and has not been demonstrated**; public MCP success alone is not Muse acceptance.

Both Pages and the optional standalone Workers path serve a public, read-only **synthetic demo**. Neither is a live merchant integration, OAuth server, purchase service, or evidence of Muse approval. A purchased domain is not required. Account terms and onboarding remain actions for the account owner.

## Current path: Pages Advanced Mode

From the repository root, with Python 3.10+ and Node 24 available:

```sh
pip install -e '.[dev]'
python scripts/build_cloudflare_demo.py
# Use pnpm 11.25.0, matching cloudflare/package.json.
pnpm --dir cloudflare install --frozen-lockfile --reporter=append-only
pnpm --dir cloudflare run build:pages
python scripts/package_cloudflare_pages.py
```

`build:pages` runs `cloudflare/build-pages.mjs`, which first builds the static site and then bundles `pages-entry.mjs` into `cloudflare/public/_worker.js` with **esbuild 0.28.2**. The pinned package versions and `pnpm-lock.yaml` define build dependencies. `package_cloudflare_pages.py` creates `artifacts/cloudflare-pages/miseport-pages.zip` plus a file/hash manifest from the contents of `cloudflare/public/`.

The upload ZIP has `index.html`, `_worker.js`, privacy/terms pages, documentation and assets at its root; it must not contain an extra enclosing `public/` folder. Use this **Pages** bundle for Pages Advanced Mode, rather than uploading only the static HTML or the Python package. The deployment UI or authorized CLI upload is a separate operation. Verify the resulting project hostname before claiming the default target is live.

`MISEPORT_PUBLIC_ORIGIN` defaults to `https://miseport.pages.dev` during build. A different project name or deployment hostname requires rebuilding with its exact HTTPS origin. `pages-entry.mjs` compiles that host into the allowlist and adds the exact `https://muse.ai` browser origin. Static assets use the Pages `ASSETS` binding. An allowed Muse origin is an Origin policy only, not proof of Muse authentication or protocol compatibility. Preview hostnames are not automatically allowed by a production-host build.

## Optional path: standalone Workers

`cloudflare/wrangler.jsonc` and `worker.mjs` retain the standalone Workers deployment path. `pnpm --dir cloudflare run build` prepares static assets; the optional Workers deployment command is `pnpm --dir cloudflare run deploy`. That command performs an external deployment and is separate from the local preparation commands above. A Workers project uses its own assigned `workers.dev` hostname and requires exact `MISEPORT_ALLOWED_HOSTS` configuration; its hostname is not the Pages hostname. Do not upload the Pages ZIP as though it were a Workers source project, or describe a Workers dry run as a Pages deployment.

## Source and reproducibility

`cloudflare/generated-catalog.mjs` is generated by the Python-side build workflow. Its default export contains `products`, `metadata`, `version`, and `tools`. Product records are fully validated by Python before generation; tool schemas come from the actual FastMCP server, rather than hand-written marketing descriptions. No runtime fetch, SDK, database, Durable Object, credential, or paid resource is used by the adapter.

`catalog.mjs` mirrors Python search, detail, inventory, nonbinding quote, audit, and JSON-LD. It keeps all product fields and timestamp offsets. The public runtime rejects empty catalogs and any product whose `is_demo` is not explicitly true. Metadata declaring `demo_only: false` is also refused. It rejects integers or computed amounts beyond JavaScript's safe integer precision instead of rounding them. Search uses NFKC, lowercase with common casefold corrections including ß and final sigma, then katakana-to-hiragana conversion. This is deterministic substring search, not semantic ranking; uncommon Unicode casefold differences can still exist between Python and JavaScript.

The main build also generates `cloudflare/contract-cases.json` from Python results. Run:

```sh
node --test cloudflare/test_worker.mjs
```

The test must find generated contract cases for all six operations. Missing fixtures fail the test; it does not substitute old test-pass claims. It also covers strict tool arguments, method negotiation, Origin/Host checks, body bounds, missing SKUs, public-demo refusal and rate-limit behavior. Local Node tests do not establish a successful Cloudflare deployment or a Muse connection.

Local result on 2026-10-29: the default Node test runner was prevented from spawning its child process by the workspace sandbox (`spawn EPERM`); no tests executed in that attempt. Use `node --test --test-isolation=none cloudflare/test_worker.mjs` in that sandbox. This alternative keeps tests in the current process and does not disable argument or security checks. The suite includes 33 generated Python contract cases and a real 15-second stalled-body timeout check; use the latest test output as the pass/fail record.

## Runtime bindings and configuration

- `ASSETS`: the static asset binding used for non-API routes.
- `MISEPORT_ALLOWED_HOSTS`: required comma-separated **exact** hosts, including a port where applicable. Standalone Workers example: `miseport.example-account.workers.dev`. For Pages, `pages-entry.mjs` supplies the compiled target, default `miseport.pages.dev`. Wildcards, schemes and paths are rejected. Missing configuration fails closed with HTTP 503. A Host mismatch returns 421.
- `MISEPORT_ALLOWED_ORIGINS`: optional comma-separated exact browser origins. The request's own origin is allowed; other present Origins must be listed. Unknown Origin and literal `null` are denied unless explicitly listed. Do not add unrelated origins.

Do not put secrets into either allowlist. During local tests, use `MISEPORT_ALLOWED_HOSTS=demo.example` and the matching request URL. Production must use the actual assigned hostname. Neither an allowlist nor an Origin check authenticates a client: requests without Origin can read this intentionally public demo.

Deployment configuration, catalog generation and static-site packaging are managed by the main project workflow. Confirm the exact hostname before deploying. This adapter does not create an account, accept terms, choose a paid plan, purchase a domain, or deploy itself.

## Source distributions and CI

Source archives include `Dockerfile.http` and the Cloudflare modules, fixtures, fixed-version package metadata, lockfile and build entry points. They exclude `cloudflare/node_modules/`, generated `cloudflare/public/`, `.wrangler/` caches and bundle output. Rebuild deployable output from the included source; the source ZIP/sdist and Pages upload ZIP serve different purposes.

The `cloudflare-pages` CI job uses Node 24, pnpm 11.25.0, frozen dependencies and an explicit esbuild 0.28.2 check. It regenerates the catalog/contracts, runs Node tests, builds/packages Pages output, and invokes the bundled Worker in-process to verify demo readiness. Dependency-install output is kept out of routine logs; failures show the final 80 log lines. The job performs no deployment, uses no Cloudflare credentials and does not claim that Pages or Muse has accepted the service.

## Routes

| Method / route | Behavior |
|---|---|
| POST `/mcp` | JSON-only, stateless Streamable HTTP MCP |
| GET `/healthz` | Readiness and demo product count |
| GET `/about` | Scope, version and limitations |
| GET `/api/products` | Search with `query`, `category`, price bounds, `in_stock_only`, `limit`, `offset`, `gift_wrapping`, `origin_prefecture` |
| GET `/api/products/:sku` | Full product and provenance |
| GET `/api/inventory/:sku` | Dated recorded availability and quantity |
| GET `/api/quote/:sku?quantity=2` | Nonbinding amount; quantity must be 1..1000 |
| GET `/api/products/:sku/jsonld` | Snapshot Schema.org Product/Offer export |
| GET `/api/audit` | Missing fields and limited catalog checks |
| GET `/openapi.json` | REST OpenAPI description |
| Other static routes | Forward to `env.ASSETS.fetch(request)` |

Missing SKU results keep Python's JSON shape and use HTTP 404. Unknown/repeated REST parameters return 400. REST booleans use exact `true`/`false`; integers use decimal digits and safe precision. No REST writes are supported. Query responses are not reservations, live inventory, verified merchant facts, or checkout quotes.

## MCP behavior

The target protocol version is `2025-11-25`. `initialize` always negotiates that supported target, including when an older client proposes a different version; the client must decide whether it can continue. No session ID is issued. Missing protocol-version headers use the compatible `2025-03-26` baseline, while unsupported explicit headers are rejected with 400. This does not implement the deprecated separate SSE transport.

Clients must POST `Content-Type: application/json` and advertise both `application/json` and `text/event-stream` in Accept. Responses use JSON. GET and DELETE `/mcp` return 405. Initialized and other accepted notifications return empty 202 responses. Supported request methods are `initialize`, `ping`, `tools/list` and `tools/call`. Unknown request methods produce JSON-RPC errors. There are no server-initiated messages, subscriptions, tasks, resource access or streaming responses.

Tool discovery retains generated Python schemas and read-only annotations. Tool arguments are closed objects: unknown properties, missing required values and incorrect types are rejected. Successful calls return both text content and `structuredContent`; tool failures set `isError`. Data remains in an immutable in-memory catalog. There is no cross-request session state, so the Worker cannot independently enforce initialization ordering for each anonymous client.

The body reader enforces a 64 KiB limit against actual streamed bytes as well as declared Content-Length, with a total 15-second read deadline returning HTTP 408. Timed-out streams are cancelled without awaiting their cancellation callbacks. Rate limiting is best-effort **per isolate**, using Cloudflare's `CF-Connecting-IP` and 120 dynamic requests per minute per address. `X-Forwarded-For` is ignored. At most 1024 active address buckets are retained; key churn fails closed. Isolate restarts and multiple isolates reset or distribute these counters, so this is not a global quota or a substitute for production edge abuse controls. Static assets are not counted by this in-memory API limiter. Do not assume the free service tier guarantees availability or unlimited traffic.
