# MisePort 2026-11-10 商店実用版 — Release Contract（必須ゲート）

**決定日:** 2026-10-29 JST  
**期限:** 2026-11-10 JST（固定）  
**製品目標:** **実際の商店が自店の商品を取り込み、確認し、自店が管理する場所へAI向けの公開情報を出せること。さらに2026-11-10に、営業中の日本のEC商店1店以上から明示的な掲載許可を得て、実商品を用いた公開デモを提示すること。**  
**状態:** 開発目標・受入契約。**現在この機能は未実装・未受入**。既存の「架空商品デモのみでv0.1正式公開」という旧プランを本契約で置き換える。

## 1. 11月10日に求めるユーザージャーニー

1. 日本の商店主がMisePortをダウンロードして起動する。通常操作にPython・Git・Docker・ターミナルを要求しない。最初に検証するOSは**Windows 10/11**。macOSは検証できた場合のみ対応を名乗る。
2. 商店主が日本語画面で「BASE」を選び、BASE Developersで**自分で発行した`items.read`のみのPAT**を商店PC上の安全な接続画面で設定する。BASE API βはOAuth非対応でPAT期限があるため、それを日本語で案内する。MisePortの公開デモにトークンを送らない。
3. 「接続を確認」→「商品を読み込む」を押す。公式BASE API v2 β（`GET /api/items?visible=true`、必要な商品詳細／種類取得）で、**公開中の商品だけ**を取得する。ページネーション、SKU／バリエーションと出典を正しく扱う。
4. 「商品情報を確認」で価格・税込区分・送料・在庫・商品URL・画像・更新時刻などを確認する。不明値は不明のまま。問題を表示し、取得に失敗したページがあればデータを勝手に公開しない。
5. 「データを生成」で**店舗所有の公開用パッケージ**を作る。最低限、MisePort標準商品JSON、利用可能な範囲のSchema.org Product JSON-LD、読み取り専用MCP/REST配信コード・データ、手順と公開Manifestを含む。既存のECサイトを自動変更しない。
6. 手順書どおりに商店所有のCloudflare Pages等へZIPをアップロードする（**Cloudflareアカウントは商店主が用意**）。商店ごとのHTTPS URLで、外部MCPクライアントが検索・詳細取得できることをテストする。公開商品が意図どおりに表示されることを確認する。
7. 次の読み込み、差分確認、公開パッケージの再生成・再配置、公開停止までの日本語手順がある。**PCを閉じている間の無人API同期はこの版では保証しない**。
8. 短い**実画面の日本語字幕付き操作動画**が公開され、手順書・製品バージョン・実画面と一致する。

**実際に営業している日本のEC店舗**の運営者または適法に委任された担当者が協力し、店主の操作とデータ一致を実測する。合成テストショップは技術テストに利用できるが**公開実商店デモの代わりにはならない**。合成Fixtureのみ、CLIのみ、MCPプロトコル単体の成功のみでは「商店実用版」合格としない。

## 3. 実装の選択と安全性

**優先構成（G1評価を即時実施）:** 既存Python商品Core + BASE SourceAdapter + 日本語ローカルGUI（127.0.0.1に限定したブラウザUI等）+ Windowsワンクリック配布。将来のほかのプラットフォーム用Adapterを差し込める構造とする。

- APIクライアントは`https://apiv2.thebase.com`の公式ホストだけに接続し、期限・403/401・429・タイムアウト・途切れたページ取得を明示的に処理する。
- API認証は**商店自身のPCのOS資格情報ストア**などで管理し、平文JSON/ローカルStorage/ブラウザ公開JS/ログへの保存を禁止する。資格情報管理方式が安全に実装・検証できなければ実店舗接続を公開しない。
- ローカルGUIではHost/Origin/CSRF/要求の認証を検証し、`127.0.0.1`以外を待ち受けない。商品名や説明に含まれるプロンプトは命令として実行しない。
- APIからは下書き・非公開商品も取得できるため、デフォルトで`visible=true`を要求し、処理後も公開フラグを再検証する。秘密、注文、顧客、未公開商品を出力しない。
- API取得失敗・部分結果では**以前の完全な公開スナップショットを上書きしない**。原点・最終取得時刻・カタログバージョン・生成ファイルを記録する。
- 独立したCloudflare ZIPの公開機能は現在の架空デモWorkerを参考に再利用できるが、**`is_demo=true`限定の公開Workerを無理やり本物商品対応に変更してはいけない**。商店専用の明示的な安全・権利確認を通す別配布物／ビルドターゲットとして開発する。
- 日本語の手順書と実録動画は実装後の実機画面から作る。画像生成UIを「本番画面」として表示しない。

**重要な依存:** 10/31までに実際に営業している協力候補を選び、11/01までに明示的な協力・掲載同意と、BASEであれば商店所有の許可済み読み取りPATを利用できる試験環境を用意する（トークンをIssueやチャットに転送しない）。ない場合はアダプターのモック試験は可能でも、11/10の「実用版」受入証明は成立しない。開発者は権限を持たない実店舗へ接続しない。

## 5. 最終受入シート（Yes/No）

- [ ] OSサポートを明記し、Windowsのテスト用商店PC上で**ダブルクリック起動、Python/Git不要**。
- [ ] 商店所有のBASE v2 β PATで、読み取り専用の接続・商品全件取得・種類の維持・再取得が**実APIで成功**。
- [ ] 商品SKU/名前/価格/公開状態/リンク/最終更新が管理画面の原本と一致。不明な送料・税は推測しない。
- [ ] 非公開・下書き・秘密・顧客情報が配布物とロギングに0件。PAT失効と解除、401/403、429、ネットワーク断を検証。
- [ ] 商店が自分のCloudflareアカウントにZIPをアップロードでき、MisePortプロジェクトのデモURLと別の**商店所有HTTPS/MCP URL**から読むことができる。
- [ ] 公開情報の更新・削除または停止が手順どおり反映される。API失敗で最後の正常なデータを失わない。
- [ ] 日本語スクリーンショット手順書、字幕つき**実画面**動画、使えるサンプルが公開される。
- [ ] 非技術協力者が実際に一連の操作を行い、所要時間・詰まった点・制限を記録した。
- [ ] **営業中の実店舗1店以上**について、取得許諾・掲載許諾・最終OKを別々に取得し、商品照会が実際に動く公開ケースを11/10に提示。協力店は架空データではない。
- [ ] Releaseのバイナリ・ソース・バージョン・checksums・実証済み対応範囲が公開され、最新のテストが緑.

**判断ルール:** 11/10は**商店向け利用可能性のハード要件**。P0が未完了なら、「実用版」と偽って公開しない。どの条件が欠けたかを記録し、最優先で修復する。11/10にP0を達成できるよう他の機能を削るのであり、P0を「v0.2で実装」に繰り下げない。
