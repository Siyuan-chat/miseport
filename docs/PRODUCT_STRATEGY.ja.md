# MisePort 製品方針 — 商店所有・ローカルファースト（ADR-0001）

**決定日:** 2026-10-29 JST  
**状態:** 製品方向を採用。以下の将来機能は実装・検証済みを意味しない。  
**対象:** 日本の小規模EC事業者と、それを支援する開発者  
**短い定義:** *商店が自分の商品情報と公開先を所有し、MisePortはAIエージェント向けの検証・変換・公開を容易にするオープンソースツール。*

## 1. 決定

MisePortは「各商店が使うツール」を主製品とし、**商品を集約する中央マーケットプレイス／比較サイトを開発しない**。

- **Merchant-owned:** 店舗・商品データ、公開先、公開範囲、更新・取り下げの判断は商店が管理する。MisePort運営者のサーバーへの商品提出やアカウント作成を必須にしない。
- **Local-first:** 商品CSV/JSONの取込・検証・修正候補のプレビュー・エクスポートは、将来のブラウザ版で原則クライアント側で実行し、秘密情報を送信しない。現行版のPython CLIは開発者向けとして残す。
- **Free-first:** ソフトウェアはApache-2.0で無償配布する。無料枠の範囲で使える公開方法を優先し、外部サービスのアカウント・料金・制限は明示する。「完全無料」「永久無料」を無条件に保証しない。
- **No-code first:** 商店の通常操作で、Python、Git、Docker、APIキー、サーバー管理を要求しない。必要なクラウド登録・権限承認は、隠さず少ない画面で案内する。
- **Open interoperability:** 中立なデータ契約と出力アダプターを用意し、将来のプラットフォームや第三者サービスが商品情報を利用できるようにする。ただし、中央の商品検索インデックス、送客仲介、決済処理は必須構成にしない。

## 2. 商店の理想的な操作（未実装のユーザー体験）

1. **開く:** ウェブ画面を開く。アカウント登録はデータ準備には不要。
2. **取り込む:** BASE / makeshop / EC-CUBE / 他のECのCSV、または標準CSV/JSONをドラッグ＆ドロップする。プラットフォーム別テンプレートと列マッピングを支援する。
3. **確認する:** 必須項目、価格（JPY）、税、配送、在庫、URL、証拠、更新時刻を検査し、未確認を「不明」のまま表示する。推奨内容は商店が確認する。AIによる商品事実の自動生成はしない。
4. **生成する:** バージョン付きカタログ、監査結果、JSON-LD、将来の公開用データフィード、必要ならデモ限定のMCP/REST配信パッケージを生成する。
5. **公開する:** 「ダウンロードのみ」または「商店所有の公開先に配置」を選ぶ。最低限、ブラウザで生成した配信ZIPをCloudflare Pages等に手動アップロードする方式を検証する。将来のワンクリック公開は別途実装・実機テストする。
6. **検証・更新する:** URL・構造化データ・対応クライアントで実際の取得を検査する。CSV再アップロードで再生成でき、更新前後の差分と記録日時を確認できるようにする。

**注意:** JSON-LDファイルを生成するだけで既存ECサイトの検索表示が変わるわけではない。既存の商品ページに規約上許される方法で組み込むか、プラットフォームがサポートするフィード等へ提供する必要がある。独立した公開MCPがあっても、すべてのAgentが自動発見・自動利用するわけではない。対応クライアント側の接続・発見・権限が必要。

## 3. 二つの利用モード

| モード | 対象 | 料金・必要条件 | 実際の公開効果 |
|---|---|---|---|
| **準備モード（最優先）** | 登録せず商品を整理したい商店 | ブラウザでCSV/JSON検証・エクスポート、アカウント不要を目標 | データや構造化マークアップの成果物を生成。オンラインのMCP呼び出しは不可 |
| **公開モード（任意）** | Agentから商品情報を呼び出させたい商店 | 商店管理のHTTPS公開先が必要。無料枠サービスの制約・アカウントがあり得る | 公開したURLで読み取り専用API/MCPを提供。Agentによる発見と連携は別途検証 |

Cloudflareは候補であり、唯一の必須ホストにしない。手動Direct Uploadは簡単な最初の経路になり得るが、更新のたびにアップロードを行う必要がある。アカウント登録を伴う「Deploy to Cloudflare」ボタンは開発者向けの補助経路として検討する。いずれも現行の公開デモが他店の運用可能なプロダクトを証明したことにはならない。

資料（2026-10-29確認）: [Cloudflare Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/), [Deploy to Cloudflare](https://developers.cloudflare.com/workers/platform/deploy-buttons/), [Workers Free limits](https://developers.cloudflare.com/workers/platform/limits/)。

## 4. 技術構成と変更しない境界

```text
Merchant-owned CSV / JSON / future authorized platform API
               │
               ▼
     Importer / source adapter
               │
               ▼
  Canonical Catalog + Evidence + Timestamp
       Versioned deterministic core
               │
     ┌─────────┴─────────┐
     ▼                   ▼
 Audit / merchant UI    Export adapters
                         ├── CSV / JSON package
                         ├── Product / Offer JSON-LD
                         ├── future merchant/feed formats
                         ├── read-only REST/OpenAPI
                         └── read-only MCP endpoint (requires a host)
                                  │
                                  ▼
                        Compatible Agent clients
```

**単一店舗・単一公開先を基本構成とする。** 中央店舗登録、巨大商品検索インデックス、横断価格比較、決済、マルチテナントSaaSを初期製品の前提にしない。MisePort公式サイトはプロジェクト紹介とデモだけを管理し、第三者の本番商品データを無断収集・保存しない。

現行コードはPythonのカタログ・MCPと、Cloudflare用JavaScriptアダプターに分かれる。継続してスキーマ／Golden Fixtures／契約テストで挙動を照合し、価格計算・未確認値・出典の意味を独立実装間で変化させない。共通仕様の最新ベースラインは現行 `miseport/1.1` と `docs/CATALOG.md`。新しい公開版を作るときはスキーマをバージョン管理し、旧版を黙って変更しない。

### 最小限の公開契約（提案）

- `CatalogSnapshot`: `schema_version`, `merchant`, `products`, `snapshot_at`, `source/evidence` を含む、または現在の契約で表現できるバージョン付き商品集合。
- `Importer`: 外部CSV/JSON・将来のAPIレスポンスをCanonical Catalogへ変換する責務。ショップへのログインや他社サービス認証はコアに含めない。
- `Exporter`: Canonical Catalogから静的データ、構造化マークアップ、MCP/REST配信用パッケージを生成する責務。
- `CapabilityManifest`（将来提案）: 利用できるエンドポイント、読み取り／書き込みの区分、ホスト、データの最終更新時刻、デモか実データかを明示する。独自プロトコルを「標準」と主張しない。
- 誰でも将来のAdapterを作れる構造を維持するが、全プラットフォーム用コネクタを最初から実装しない。

値の由来と未確認の区別を最優先する。商品説明等は命令ではなく未信頼データとして扱う。実店舗データを公開する前に権利、プライバシー、認証、更新・削除フローを確認する。

## 5. MVPで採用するもの／採用しないもの

| 優先 | 対象 |
|---|---|
| **MVP 1** | ブラウザ中心の日本語CSV取込・列マッピング・プレビュー・検証・監査・ダウンロード。ローカル処理とデータ非送信をテストで確認 |
| **MVP 2** | デプロイ可能な商店別静的パッケージ（JSON-LD・商品データ・必要に応じて読み取り専用MCP）。手動アップロードと更新を一人の非技術ユーザーで実測 |
| **MVP 3** | 最初の実ショップPilot。エクスポート権限、データ品質、公開先、Agent回答の正確さと必要工数を測定 |
| **後続** | BASE / makeshop / EC-CUBEの個別Adapter、差分同期、Webhook、GEO評価、複数チャネル出力 |
| **対象外（当面）** | 大規模中央検索・比較サイト、価格比較ネットワーク、商家からの取引手数料、決済・返金、複雑な会員制度、大規模マルチテナント基盤 |

商家向けの価値指標は検索順位の保証ではなく、**インポート～準備完了までの時間、手作業件数、重要属性の欠損率、Agent回答の正確さ、更新のしやすさ**とする。最初のUX目標は「技術者の説明なしで10分以内にCSVから成果物をダウンロードできる」だが、これは**未測定の目標値**である。

## 6. 今の実装との位置づけ

2026-10-29時点でPython CLIのCSV/JSON取込・検証、監査、JSON-LD、7つの読み取り専用MCPツール、架空商品による公開Cloudflareデモ、アカウント内Muse接続検証は記録済み。商家向けブラウザインポート・編集画面、実ショップ専用公開ZIPの自動作成、一クリック公開、プラットフォーム原生同期、GEO成果分析は**未実装**。

**2026-11-10の短期ゴール**は既存OSSの品質・文書・リリースとテストを仕上げること。非技術ユーザー向けの本格的な操作体験は次の開発段階として扱う。現状のCLIと公開架空デモを、一般商店が今すぐセルフサービスで使えると宣伝しない。
