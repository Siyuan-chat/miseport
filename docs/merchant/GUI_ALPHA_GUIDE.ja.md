# MisePort 商店向け GUI Alpha — 操作手順

> **Alpha・開発者による動作確認用。本番の商店利用は未認定です。**
> 2026-10-29。現在は実画面のスクリーンショット・録画・本物のショップの受入は未完了です。

## 何ができるか

公式 BASE API β の商品情報を読み取り専用で取得し、商店自身のPC上で価格・在庫スナップショットを確認します。認可済みの商品URLを登録すると、標準カタログJSON、Cloudflare Pages向けの読み取り専用 MCP/REST ZIP を生成できます。これは店舗の注文・決済・商品更新や、Museの公式承認を意味しません。

## 実装済み GUI の操作順

1. **① 店舗情報と BASE PAT:** ショップオーナー本人が BASE Developers で items.read のみを付けた PAT を発行。店舗ID、店舗名、店舗トップURLを入力し、PATをMisePortのローカル画面で入力する。公開 Demo・Issue・メールには貼らない。
2. **② BASEから商品を読み込む:** 公式APIに HTTPS GET。PATは入力欄から直ちに消去され、ファイルへ保存しない。APIの失効・権限不足・利用上限・通信失敗を日本語で表示する。
3. **③ 商品一覧:** 商品名、税込価格、在庫記録、公開状態を確認する。特殊な販売方式やオプション料金は未対応で、公開用Catalogから除外または要確認になる。
4. **④ 商品URLの候補を一括生成:** 店舗トップURLが正しいことを確認したうえで、BASEの公開商品ページを一つ開き、そのURLを「実際に確認した1商品のURL」に入力する。「商品URLの候補を一括生成」を押し、BASE公式の「/items/商品ID」形式で他商品の候補を自動作成する。**一括生成はURL形式の推測であり、全件のHTTP到達性/ページ内容を独立検証したものではない**。店主は生成結果を確認でき、必要なら手動修正できる。
5. **⑤ データの確認:** 不明価格や未確認URLがあれば公開をブロックする。商品URLを変更した場合は必ず再審査。URLが他店舗に属する、商品IDと異なるページを指す場合も拒否する。合格した場合のみJSON/ZIPボタンが有効になる。
6. **⑥ 出力と差分確認:** 店主が公開内容を確認してJSON保存または「商店用MCP/REST ZIPを生成」を選ぶ。すでにJSONを保存していた場合は新旧商品を比較し、公開対象から消えた商品があれば確認を求める。API/変換の一部失敗では旧ファイルを上書きしない。ZIP生成時は商店所有の正確なHTTPS公開先を入力する。
7. **⑦ 手動公開:** ZIPは自動的にインターネットへ公開されない。Cloudflare Pages等の商店自身のアカウントでアップロードし、URLとMCPの動作を確認する。公開停止も店主側で実行する。

## Alphaの現在の制限

- 開発者は Python 環境から GUI を起動できる。通常の商店ユーザーには **Windows Alpha EXE** の実機受入まで正式配布しない。
- PATは**会話セッション/プロセス内の一時使用のみ**を優先しており、長期保存・24時間自動同期はできない。
- BASEの商品公開URLは公式ルートを使って**一括候補生成**できるが、店主が少なくとも1件の実商品を確認し、全体を公開することを承認する必要がある。公開商品ページ全件のネットワーク検証はまだ未実装。
- Cloudflare用ZIPのNode/API契約テストは実施しているが、商店自身の公開アカウントでの実運用は未検証。
- 送料不明と現在庫の不確実性を保持する。公開用ZIPから顧客/注文/認証情報を必ず除外する。
- 旧 https://miseport.pages.dev/mcp の実測は**架空商品に限る**。商店用ZIPをMuseで受け入れた証拠ではない。
