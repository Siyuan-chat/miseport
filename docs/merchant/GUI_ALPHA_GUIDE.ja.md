# MisePort 商店向け GUI Alpha — 操作手順

> **Alpha・開発者による動作確認用。本番の商店利用は未認定です。**
> 2026-10-29。現在は実画面のスクリーンショット・録画・本物のショップの受入は未完了です。

## 何ができるか

公式 BASE API β の商品情報を読み取り専用で取得し、商店自身のPC上で価格・在庫スナップショットを確認します。認可済みの商品URLを登録すると、標準カタログJSON、Cloudflare Pages向けの読み取り専用 MCP/REST ZIP を生成できます。これは店舗の注文・決済・商品更新や、Museの公式承認を意味しません。

## 実装済み GUI の操作順

1. **① 店舗情報と BASE PAT:** ショップオーナー本人が BASE Developers で items.read のみを付けた PAT を発行。店舗ID、店舗名、店舗トップURLを入力し、PATをMisePortのローカル画面で入力する。公開 Demo・Issue・メールには貼らない。
2. **② BASEから商品を読み込む:** 公式APIに HTTPS GET。PATは入力欄から直ちに消去され、ファイルへ保存しない。APIの失効・権限不足・利用上限・通信失敗を日本語で表示する。
3. **③ 商品一覧:** 商品名、税込価格、在庫記録、公開状態を確認する。特殊な販売方式やオプション料金は未対応で、公開用Catalogから除外または要確認になる。
4. **④ 商品URLの候補を一括生成:** 店舗トップURLが正しいことを確認したうえで、BASEの公開商品ページを一つ開き、そのURLを「実際に確認した1商品のURL」に入力する。「商品URLの候補を一括生成」を押し、BASE公式の「/items/商品ID」形式で他商品の候補を自動作成する。**一括生成はURL形式の推測であり、全件のHTTP到達性/ページ内容を独立検証したものではない**。店主は生成結果を確認でき、必要なら手動修正できる。
5. **⑤ データの確認:** 不明価格や未確認URLがあれば公開をブロックする。商品URLを変更した場合は必ず再審査。URLが他店舗に属する、商品IDと異なるページを指す場合も拒否する。合格した場合のみJSON/ZIPボタンが有効になる。
6. **⑥ 出力と差分確認:** 店主が公開内容を確認してJSON保存または「商店用MCP/REST ZIPを生成」を選ぶ。すでにJSONを保存していた場合は新旧商品を比較し、公開対象から消えた商品があれば確認を求める。API/変換の一部失敗では旧ファイルを上書きしない。ZIP生成時は商店所有の正確なHTTPS公開先を入力する。
7. **⑦ 手動公開:** ZIPは自動的にインターネットへ公開されない。Cloudflare Pages等の商店自身のアカウントでアップロードし、URLとMCPの動作を確認する。公開停止も店主側で実行する。

## BASE / Shopify 商品CSVの読み取り（APIキーなし）

現在のAlphaには、**「BASEの商品CSV」「Shopifyの商品CSV」**を選び、ファイルを読み込む試作入口があります。API連携が未許可でも、商店が公式にエクスポートした**商品情報だけ**を自分のPC内で確認できます。注文・顧客CSVは受け付けません。

1. 自分の店舗トップURL、店舗ID、店舗名を入力し、実際の公開商品URLを1件確認して画面に入力する。
2. 「APIを使わない場合」のプラットフォームを選び、「商品CSVを選ぶ（読み取り専用）」を押す。ファイルはアップロードされずローカルで解析する。
3. **BASE:** 公式「CSV商品管理 App」の**既存商品の商品CSV**を選ぶ。UTF-8 / Shift_JIS（CP932）に対応。公開状態、商品ID、種類ID、価格などの列を確認する。新規登録用のID空欄の行は公開できない。
4. **Shopify:** 公式の商品CSVをUTF-8で保存して選ぶ。販売通貨がJPYであることを確認する。単一在庫拠点かどうかを回答する。複数拠点または不明の場合、在庫数量を「不明」のまま扱う。旧形式と新形式の主要商品CSV列に対応する試作であり、すべてのカスタムCSV書式を保証しない。
5. 「④ データの確認」で、変換できなかった商品、非公開商品、価格・在庫・送料の欠落を確認する。問題のある場合は出力をブロックする。
6. 問題がない場合、商品JSONまたは商店専用ZIPを生成できる。**元のECサイトへのCSV再アップロードや商品更新は行わない。**

**重要:** これらのCSVには信頼できる元商品更新日時が含まれないことがあり、MisePortは**商店が内容を確認した時刻**を記録します。これを元ショップの実際の最終編集日時と混同しないでください。商品URLはプラットフォームの正式な経路から作る候補であり、全商品のネットワーク検証ではありません。

公式資料：[BASE CSV商品管理](https://help.thebase.in/hc/ja/articles/900000043803)・[Shopify商品CSV](https://help.shopify.com/ja/manual/products/import-export/using-csv)。

## 公開商品URLの一括確認（開発版）

BASE APIから商品を読み、店主が実際の1商品を確認して候補URLを一括生成した後は、**「公開商品URLを最大30件確認」**を選べます。**店主本人が明示的に承認したときだけ**、同じショップの公開HTTPSページを取得して確認します。BASEのPAT、ログイン情報、Cookieは一切送られません。

確認できる範囲には限界があります。HTTP 200に加え、ページ内のcanonical URLまたはOG URLが、登録した商品IDと同じ公開URLを示した場合だけ「確認」と表示します。404/410はエラー、リダイレクト・拒否・識別情報不足・大きなページなどは「要確認」と表示し、勝手に成功扱いしません。公開前に店主が内容と出典を確認してください。

**安全性と負荷:** 最大30件／操作、4秒の既定タイムアウト、同一ショップのHTTPSのみ、公開インターネットIPへTLS検証済みの通信を行います。リダイレクトは追いません。アクセスできるページでも、価格・在庫の最新性や実際の在庫確保は保証しません。利用規約やアクセス制限がある店舗では検査を行わず手動で確認してください。

## Cloudflare Pagesへの手動公開（開発版）

ZIP生成後に **「⑦ Cloudflare公開手順」** から操作手順を開けます。管理画面を開くボタン、公式手順へのリンク、MCP URLのコピーが用意されています。

1. ZIPを保存したPCの商店主自身のアカウントで [Cloudflare Dashboard](https://dash.cloudflare.com/) にログイン。
2. 「Workers & Pages」→「Create application」→「Get started」→「Drag and drop your files」を選びます。作成時のプロジェクト名と、MisePortのZIP生成時に指定したHTTPS公開先が一致することを確認します。
3. ZIPをアップロードし、内容・公開範囲を確認してデプロイします。Direct UploadからGit連携プロジェクトへの切替えはそのままではできないため、将来の運用方法を考えて選んでください。
4. 公開したページと /healthz・/api/products を自分のブラウザで確認。MCP利用は対応クライアントで **/mcp** に接続して tools/list と検索動作を確認します。
5. 更新・削除する際は新しいZIPで再デプロイ、またはCloudflare管理画面から公開を止めてください。過去に取得された商品データのキャッシュは自動で消えるとは限りません。

詳しい公式説明: [Cloudflare Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)。**MisePortのGUIは商店のCloudflareアカウントを管理しません。** ZIP生成と「インターネットへの公開成功」は別です。

## Alphaの現在の制限

- 開発者は Python 環境から GUI を起動できる。通常の商店ユーザーには **Windows Alpha EXE** の実機受入まで正式配布しない。
- PATは**ローカルプロセス内の一時使用のみ**を優先しており、長期保存・24時間自動同期はできない。商品CSVを選ぶ場合はPAT不要。
- BASEの商品公開URLは公式ルートから**一括候補生成**でき、店主が承認した最大30件について公開ページのURL識別情報をネットワーク照合できます。ただし候補全件の検証成功を保証せず、残りや「要確認」結果は店主自身の確認が必要です。
- Cloudflare用ZIPのNode/API契約テストは実施しているが、商店自身の公開アカウントでの実運用は未検証。
- 送料不明と現在庫の不確実性を保持する。公開用ZIPから顧客/注文/認証情報を必ず除外する。
- 旧 https://miseport.pages.dev/mcp の実測は**架空商品に限る**。商店用ZIPをMuseで受け入れた証拠ではない。

## 商店専用ZIPの公開前チェック（Alpha）

MisePortのZIP生成コードは、**正常な旧ZIPを上書きする前に**公開用ファイルの一覧とハッシュ・生成した商品CatalogとMCP Workerの一致・公開先ドメインを確認します。検証に失敗した場合は旧ファイルを維持し、配信を行いません。

技術者が手動で検証する場合は、開発環境で `miseport-verify-bundle merchant.zip --origin https://your-store.pages.dev` を実行できます。返却されるのは検証結果であり、**クラウドへのデプロイやMuseからの到達確認ではありません**。商店が商品公開を許可したことの法的証明や最新の在庫保証でもありません。
