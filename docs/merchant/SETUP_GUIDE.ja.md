# MisePort 店舗オーナー向け操作手順書（日本語）

**更新:** 2026-10-29 JST  
**対象:** コードを書かずに自分のネットショップをAI対応させたい店主  
**製品状態:** 「現在試せること」と「開発予定の画面」を明確に分けています。**MisePort公式サイトに実ショップのAPIキーを入力する画面はまだありません。**

## まず知っておいてください

MisePortはショップの商品の「名前・商品ページURL・価格・在庫状態・送料・更新日時」などを整えて、AIが商品を確認しやすくするオープンソースの道具です。**現在の公開デモは架空の商品専用**で、買い物や商品登録はできません。AIによる推薦や売上増加を保証するものでもありません。

やりたいことを選びましょう。

| やりたいこと | 今できる？ | 次の操作 |
|---|---|---|
| どんな画面・商品検索か知りたい | **はい（架空デモ）** | [デモサイト](https://miseport.pages.dev/)へ |
| 自分の商品CSV/JSONを開発者に検証してもらう | **はい（開発者用CLI）** | [README](../../README.md)のローカル手順を参照 |
| 自分のショップに接続して商品を自動で読む | **BASE read-onlyローカルGUI Alphaあり（実商店未受入）** | [Alpha手順](GUI_ALPHA_GUIDE.ja.md)と[API接続設計](../CONNECTOR_ARCHITECTURE.ja.md)へ |
| APIを使わず商品CSVを取り込む | **ローカル日語GUI Alphaのコードあり（実商店未受入）** | [GUI Alpha操作説明](GUI_ALPHA_GUIDE.ja.md)へ。Webブラウザの公開デモではできません |
| 自分のMisePort公開先をワンクリックで作る | **いいえ（開発予定）** | 公開先のアカウント・制限の確認が必要 |

## 1. 現在試せる公開デモ（実際に試せる手順）

1. ブラウザで **[https://miseport.pages.dev/](https://miseport.pages.dev/)** を開く。
2. 画面内の **「架空カタログを検索する」** を探す。
3. 入力欄に **「ほうじ茶」** と入力して、**「検索 / Search」** を選択する。
4. 商品名と価格を見て、説明に **「架空の商品」** と表示されることを確認する。
5. [接続ガイド](https://miseport.pages.dev/docs/?lang=ja)で、MCPやOpenAPIの説明を見る。

商品は実在しません。注文や購入はできません。デモ画面にパスワード・トークン・顧客情報を入力しないでください。画面が変わったらGitHubの最新READMEを確認してください。

## 2. 将来の操作: ショップを自動接続する（画面は未実装）

開発する日本語UIの画面名（**案**）と、店主の作業です。**今はまだこの通りクリックできません。**

1. **「ショップを接続」** を選ぶ。BASE、Shopify、makeshop、カラーミーショップ、EC-CUBE、STORESから自分のプラットフォームを選ぶ。
2. 接続方法が表示される。**「公式アカウントで許可する」** が使えるならOAuthを優先する。APIキー方式のショップでは、**自分で管理するローカル接続ツール／ホスト**の画面に限ってトークンを保存する。
3. **「接続テスト」** を選ぶ。接続できなかった場合は権限、プラン、APIの有効化、接続先、期限を確認し、理由を表示する。
4. **「商品を読み込む」** を選ぶ。初回は**公開中の商品だけ**が選択されているか確認する。非公開・下書き・受注・顧客情報を勝手に公開しない。
5. **「商品情報を確認」** で価格、税込、送料、在庫、商品URL、商品種類（SKU）を確認。不明なところは空欄や不明のままにする。
6. **「成果物を作成」** を選び、標準商品JSON、JSON-LD、または対象プラットフォーム向けCSVのうち**対応が検証済み**の形式を選ぶ。
7. **「ダウンロード」** または **「公開方法を案内」** に進む。オンラインのMCPを公開する場合は自分の管理するHTTPS公開先が必要。無料プランの利用制限がある場合は確認する。
8. 変更があったら **「今すぐ同期」** で再取得する。24時間の自動同期は、商店が自分の実行環境や対応するクラウド接続を用意した場合に限る。無断で定期実行しない。

このフローは開発目標であり、実際の接続画面や動画は機能実装後に再検証します。

## 3. APIキーの準備（BASE新API βを例にした事前説明）

**注意:** BASE用のAPI自動接続はまだMisePortに実装していません。ここでは公式サービス側の準備概念だけを説明します。キーを生成しても、MisePortの公開デモへ貼り付けてはいけません。

1. ショップ所有者が[BASE API β公式ドキュメント](https://apiv2.thebase.com/docs/)を開き、対象アカウントでBASE Developersへ進む。
2. 必要な場合は「Personal Access Token（PAT）」の説明に沿って発行する。**商品読み取り専用の `items.read`** を利用する設計を優先する。利用目的に必要ない注文・顧客・商品更新権限は付けない。
3. 作成したトークンをメールやGitHub Issueで共有せず、PCのパスワードマネージャー等に安全に保管する。
4. 将来MisePortの**安全なローカル接続環境**が完成した時だけ、そちらの案内に従って接続する。公開のデモWebページやフォームへ入力しない。
5. 使わなくなったらBASE側で認可を失効し、MisePort側の接続設定と公開商品データを別々に停止・削除する。

**補足:** BASE新APIはβ版で、OAuth2は将来対応予定です。ShopifyやEC-CUBEなどは異なるアプリ認可方式を使用するので、同じ「APIキー手順」を当てはめないでください。具体的な操作は各プラットフォームの最新公式説明を優先します。

## 4. APIが使えない時のCSVの取り出し方（公式資料）

商品CSVは注文CSVや顧客CSVではありません。**必ず「商品情報」だけ**を選んでください。

### BASE

1. [CSV商品管理 App の公式手順](https://help.thebase.in/hc/ja/articles/900000043803)を開く。
2. ショップ側で **CSV商品管理 App** が利用可能か確認する。
3. 必要な商品項目を選び「CSVをダウンロード」する。新規登録用と既存更新用は用途が違うため、商品確認用に必要な方を選ぶ。
4. ダウンロードしたファイルを安全に保存する。将来のMisePortに取り込む際はショップの書式を自動判定できるようにする計画です。

### Shopify

1. [商品のエクスポート（公式）](https://help.shopify.com/ja/manual/products/import-export/export-products)の手順を参照する。
2. ショップ管理画面の「商品管理」から、対象商品またはすべての商品をCSVでエクスポートする。
3. 商品・バリエーションが含まれるかを確認する。商品CSVと在庫CSVは別の場合があり、複数の在庫拠点を勝手に合算しない。

### makeshop

1. [商品情報一括アップロード・CSVダウンロード（公式）](https://manual.makeshop.jp/hc/ja/articles/53061016220441-)を開く。
2. **商品管理 → 商品一覧 → アップロード・ダウンロード → 商品情報一括アップロード・CSVダウンロード** に進む。
3. 商品の範囲とフォーマットを確認してCSVをダウンロードする。新旧フォーマットの列名が違う場合があるため、そのまま保存しておく。

### カラーミーショップ

1. [データダウンロードの使い方](https://help.shop-pro.jp/hc/ja/articles/360062479334-)を確認する。
2. 管理画面の「ダウンロード」で **商品データ** を選ぶ。顧客データ・受注データは選ばない。
3. `product.csv` などの商品CSVを保存する。文字コードは加工せず元のファイルを残す。

### EC-CUBE

1. [CSV出力項目設定の公式説明](https://www.ec-cube.net/manual/ec-cube4/setting/shop_csv.php)を見る。
2. 商品CSVの出力設定を確認し、商品ID、商品名、公開状態、商品規格、価格など必要な項目を選ぶ。
3. CSVの列選択が店舗ごとに違うことがあるため、出力項目のメモも保管する。

### STORES / Yahoo! / 楽天

アカウントのプラン・機能や管理画面によって手順が変わります。MisePortがCSVを自動判定できると確認するまでは、**公式サイトの最新の商品エクスポート方法を確認し、個人情報を含まない商品ファイルのみ**を使ってください。[対応表](../PLATFORM_COMPATIBILITY.ja.md)を参照してください。

## 5. 出力形式と注意点

| ファイル | 何に使うもの？ | 元のショップを変更する？ |
|---|---|---|
| MisePort商品JSON | 自分のデータの確認・バックアップ・別サービスへの接続 | **しない** |
| Schema.org Product JSON-LD | 許可された商品ページや他のツールで構造化情報を利用する | 生成だけではページは変わらない |
| MCP/REST用の公開パッケージ | 許可した商品情報を外部Agentから読む（公開先が必要） | **しない** |
| 各ショップ専用のCSV（開発予定） | プラットフォーム仕様に沿うCSVとしてのファイル出力 | **ファイル出力だけならしない**。ショップにアップロードすると更新が発生し得る |

**重要:** 出力先ショップのCSVを再アップロードすると価格・画像・バリエーションなどが変更される可能性があります。MisePortは**当面ショップへの書き戻しを実行しません**。

## 6. 困った時に確認すること

| 状況 | 確認すること |
|---|---|
| 接続できない | APIが対象プランで利用可能か、認可済みか、読み取り権限は十分か、公式API仕様が変わっていないか |
| 商品数が違う | ページ分割、非公開商品の除外、バリエーション数を確認。勝手に削除されたとは判断しない |
| 送料・税込価格が不明 | ショップの送料条件や税区分が取得元に存在するか。データを推測で補わない |
| 商品を非公開にした | 公開先データが古くないかを確認し、再同期または公開停止を行う |
| APIキーを誤って公開した | 直ちにショップ側で失効・再発行し、公開記録やログから除外する。トークンそのものはIssueに貼らない |
| Museが使ってくれない | MCP接続とツールの検出・権限を確認。公開URLの存在だけでAgentが自動利用するとは限らない |

[GitHubで不具合報告](https://github.com/Siyuan-chat/miseport/issues)する際は、ショップ名・注文情報・個人情報・秘密鍵を匿名化してください。
