# MisePort 商店オーナー向け・画面付き操作手順（Alpha）

> **作成日:** 2026-10-29  
> **状態:** Alphaの実画面を、**架空の商品データだけ**を使って撮影したガイドです。  
> **Windows実店舗での動作・非技術者による受入は未完了**です。本番の商店接続やMeta Museの自然検索での表示を保証しません。

## 画面写真について

- [写真の生成と自動チェック（GitHub Actions）](https://github.com/Siyuan-chat/miseport/actions/runs/40818472128) から、`miseport-actual-tk-screenshots` という期間限定Artifactを取得できます。
- `01-shops-and-products.png`: 店舗設定と「② 商品一覧」
- `02-product-review.png`: 「③ 商品URL・監査・出力」上部
- `03-publish-steps.png`: 同じページを下へスクロールした公開操作

Artifactは保存期限があります。写真・その出典とバージョンを正式リリース用の安定した公開資料に移してから、READMEに画像を埋め込むこととします。**現時点でGitHub上の恒久的な画像URLを作ったとは主張しません。**

## 1. 商品の取得方法を選ぶ

GUIを起動し、画面上部の「店舗ID」「店舗名」「店舗トップのURL」を入力します。

**BASE APIを利用する場合:** BASE Developersの正式な説明に従って、ご自身のショップ用に商品読み取り専用のPATを発行します。パスワードやPATをMisePortの公開Demo、GitHub Issue、他者のチャットへ送らないでください。ローカルGUIの「BASE PAT」に入力し、**「① BASEから商品を読み込む」**を押します。現在のAlphaはPATの保存・無人同期を行いません。

**CSVで読み込む場合:** 「APIを使わない場合」でBASEまたはShopifyの商品CSVを選び、**「商品CSVを選ぶ（読み取り専用）」**を押します。顧客や注文のCSVは使えません。Shopifyでは日本円・在庫拠点数と公開中の商品であることを確認してください。

**重要:** 取得元・店舗ID・店舗名・ホームページ・CSV種類・商品例URLを変えたら、古い商品の審査結果を転用しないように**再読込**してください。

## 2. 公開商品とURLを確認する

「② 商品一覧」で公開対象、名前、記録された価格・在庫を確認します。未知の送料や税・在庫が勝手に補われることはありません。

「③ 商品URL・監査・出力」に進み、実際の商品を1つブラウザで確認して、**「実際に確認した1商品のURL」**に入力します。BASEなら**「商品URLの候補を一括生成」**を使って、残りの商品に同じショップのURL候補を設定できます。候補はURL形式から導いたもので、すべての商品ページが正しいという証明ではありません。

ご自身のショップで閲覧可能な商品ページに限り、**「公開商品URLを最大30件確認」**を押すと、明示的な同意のもとで公開HTTPSのページ情報を検査します。確認不能・404・リダイレクト・商品の不一致があれば、手動で修正してください。BASE PATはこの検査に使いません。

**「④ データの確認」**でエラーと不明情報を確認します。改めて公開範囲を確認し、同意できる場合だけチェックを付けます。

## 3. 商品データまたはZIPを作成する

ローカル保存用の **「⑤ カタログJSONを保存」**、あるいは商店が自分で公開するための **「⑥ 商店用MCP/REST ZIPを生成」** を選びます。

- 古いカタログがある場合、商品追加・変更・削除の差分が表示されます。削除には店主の確認が必要です。
- ZIP生成時は、Cloudflare Pagesが実際に付与する予定のHTTPS公開ドメインを入力してください。
- MisePortは生成済みZIPの内容、商品とWorkerの一致をチェックします。**ZIP生成だけでは、インターネットに公開されません。**

## 4. Cloudflareで公開し、MCPを確認する

ZIPを生成した後、**「⑦ Cloudflare公開手順」**を開きます。店主のCloudflareアカウントにログインして、[Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)の公式操作に従ってファイルをアップロードします。

Cloudflareで実際に発行されたドメインと、MisePortでZIPを作ったときに指定したドメインが違う場合、**ZIPを正しいドメインで作り直してください**。MisePortのGUIはCloudflareへの自動ログインや勝手なアップロードを行いません。

公開後はGUIに戻って **「⑧ 公開後のMCP接続を確認」** を選び、読み取り専用のヘルスチェック、REST、MCPのツール呼び出しと商品情報を確認します。成功結果は、「その公開URLで商品データとMCPが取得できた」という技術的なチェックです。**Museが一般の買い物質問でショップを自動発見・推薦することを保証しません。**

## トラブル時の案内

| 表示 | 確認すること |
|---|---|
| BASE認証に失敗した | 正しいショップのPATか、items.read権限・期限・API利用条件か |
| 公開商品URLが要確認 | 同一店舗の実商品URLと商品ID・ページの公開状態、404/リダイレクト |
| 商品情報が未確認 | 価格・税・送料・公開状態・商品URLの欠損。空欄を推測で補わない |
| ZIPが生成できない | 店舗の公開許可、配信ドメイン、商品情報、保存先を確認 |
| MCP接続が失敗する | Cloudflareで実際に割り当てられたURLとZIPのURLが一致するか、配信が成功したか |
| 店舗を切り替えたい | **新しい店舗情報で再取得/再読込**してから公開可否を再確認 |

**この手順書は開発中のAlphaを説明するものです。** 日本の店舗オーナーによる実際のWindows操作、画面写真の最終確認、ショップAPIの本番適合・動画収録は引き続き必要です。関連：[Alpha使用説明](GUI_ALPHA_GUIDE.ja.md)・[Meta Muse接続案内](../MUSE_CONNECT.ja.md)。
