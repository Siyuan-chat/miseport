# MisePort 開発計画 v1.2 — 11月10日「商店実用版」＋実商店デモ

**更新日:** 2026-10-29 JST
**期限:** 2026-11-10 JST（商店実用版のハードゲート）
**状態:** PLAN_ONLY。実装済みの機能と未実装のRelease要件を混同しない。具体的な受入条件は [11/10 Release Contract](RELEASE_2026-11-10.ja.md) が優先。

## 1. 一番重要な成果物

**11/10に実際の日本のEC店舗1店以上が使えるMisePortを公開し、その店舗の許諾を得た実商品デモを公開する。** これは単なるPython/MCP Developer Demoではない。

商店主が日本語で接続→公式BASE APIから自店の商品を自動取得→商品と公開範囲を確認→自分の公開先へ配置→Agentの検索・照会を試せる。店主の一般操作ではPython・Git・Docker・ターミナルを要求しない。

**本当に営業している協力商店の同意が必要。** 架空商品、開発者が作ったサンドボックス、無許諾のスクレイピング、匿名の社内試験を「実商店の公開Demo」へ置き換えない。候補募集と公開同意のフローは [実商店Pilot](merchant/PILOT_2026-11-10.ja.md) / [Issue #9](https://github.com/Siyuan-chat/miseport/issues/9) で管理する。

## 4. 安全・技術の不可侵条件

- 既存のPython Catalog/Core（miseport/1.1）、MCP/RESTの契約テストを残す。単一商店・商店所有データ/配信URLを基本構造とし、大規模集約はしない。
- BASE新APIはβ版。公式items.read取得（GET /api/items、visible=true、必要に応じ商品詳細/種類）を使う。権限追加が必要な場合は明示し、注文/顧客や書込スコープを不要に取得しない。
- ローカルConnectorの秘密は商店PC側の安全な保管先を使い、公開Demo・公開Webアプリ・静的JS・GitHub/動画/ログに載せない。ループバックonly、Host/Origin/CSRF/要求認証と失効時のエラーをテスト。実現・検証できないならPATを収集しない。
- 公開用ZIPは、公開中の商品と商店が許可した情報だけを含む**別のビルド対象**。非公開商品、仕入先情報、注文、顧客、API資格情報、他商店のデータを絶対に含めない。
- 公開商品であっても、商店名・画像・動画・ケース公開への同意は別。本人が許可していない転載をしない。撤回や商品の非公開への追随を設計する。
- 「CSVの読込」と「ECへ再取込可能なCSV出力」と「ショップの更新操作」を混同しない。初回は読取専用、既存のEC管理画面を変更しない。
- Agentの実ツール呼出とAIによる自動発見/SEO・GEO順位は別。公開するだけでMuseに自動推薦されるとは謳わない。

| 手順/動画（Issue #4） | 日本語の本物の画面による説明、字幕、解約/削除/更新、実際の機能との一致 |
| オーナー | 実店舗候補・外部連絡の許可/実施、必要なBASEアカウントアクセス、公開審査と最終確認 |

連絡先・店主の個人情報やAPI認証情報は公開GitHub Issueに記載しない。商店の許諾と公開に必要な権利はプロジェクト運営者ではなく商店本人が確認する。

## 6. 11/10の成果の公表ルール

- P0（商店GUI・BASEの実商品自動取得・商店所有のAgent公開先・実店舗1件の公開ケース・日本語手順と実録動画・CI）が揃って初めて「商店実用版が完成」と書く。
- 公開は事前同意と実績に基づく。商店が同意を取り消したら表示を取りやめる。他社のAPI/規約が変わる場合は明示的な制約として表示。
- 11/10に追加プラットフォーム、定期同期、決済、検索流入の成果保証は不要。商店の参加や掲載は外部依存であり絶対保証しないが、日程の最優先ゲートとして追う。
- 後続のプラットフォーム追加とCSVプロファイルについては [互換性マトリクス](PLATFORM_COMPATIBILITY.ja.md) と既存GitHub Issues #3/#5で管理する。
